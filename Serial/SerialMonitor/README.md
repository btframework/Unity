# Serial Monitor — Unity Demo

A Unity example demonstrating the use of the **[Serial Framework](https://www.btframework.com/serialframework.htm)** (`wclSerialMonitor` class) to enumerate serial and USB devices, track hot-plug events, and control USB device state.

This demo is a Unity port of the reference **Serial Monitor** sample documented at:
**https://www.btframework.com/serialmonitor.htm**

---

## Overview

The example implements device discovery and hardware monitoring on Windows and macOS:

- Enumerating serial ports (COM ports, virtual COM, modems, UART devices)
- Enumerating USB devices with instance path, VID/PID, class GUID, and manufacturer
- Starting and stopping the hardware change monitor
- Reacting to device arrival and removal in real time
- Enabling and disabling USB devices by instance path (Windows)

The user interface is generated programmatically by an editor script. There are no hand-authored scenes or prefabs to maintain, which keeps the example aligned with the framework API.

---

## Features demonstrated

| Area | `wclSerialMonitor` API used |
|------|-----------------------------|
| Lifecycle | `Start`, `Stop`, `OnStarted`, `OnStopped` |
| Serial enumeration | `EnumSerialDevices`, `wclSerialDevice` (`DeviceName`, `FriendlyName`, `IsModem`) |
| USB enumeration | `EnumUsbDevices`, `wclUsbDevice` (`Instance`, `FriendlyName`, `VendorId`, `ProductId`, `ClassGuid`, `Manufacturer`, `Enabled`) |
| Hot-plug notifications | `OnSerialDeviceAdded`, `OnSerialDeviceRemoved`, `OnUsbDeviceAdded`, `OnUsbDeviceRemoved` |
| USB control (Windows) | `EnableUsbDevice`, `DisableUsbDevice` |

## Requirements

- **Unity** 2021.3 LTS or newer (TextMeshPro and the Editor API are used)
- **Serial Framework** installed and referenced by the project
  - Product page: https://www.btframework.com/serialframework.htm
  - Installation guide: https://www.btframework.com/howtoinstall.htm
- **Platforms:** Windows and macOS
  - Serial enumeration and all events work on both platforms
  - USB enumeration and USB enable/disable are Windows-only
- Both **Mono** and **IL2CPP** scripting backends are supported without additional configuration

## Getting started

### 1. Install the Serial Framework

Ensure that the Serial Framework assemblies (`wclCommon`, `wclSerialFramework`, and their dependencies) are present in the Unity project and are referenced by the assembly that contains `SerialMonitorDemo.cs`.

### 2. Build the demo scene

The UI is generated by an editor script. From the Unity menu, select:

> **Tools → Serial Monitor → Build Scene**

This operation performs the following:

- Creates the `SerialMonitorUI` canvas with the full control layout
- Creates the `SerialMonitorDemo` GameObject and wires every UI element to its corresponding field
- Creates the `SerialMonitorSerialRow`, `SerialMonitorUsbRow`, and `SerialMonitorLogRow` prefabs under `Assets/Prefabs`
- Saves the active scene so it is included in a build

After running the builder, save the scene manually (`Ctrl+S` / `Cmd+S`) if Unity does not save it automatically. The editor logs a warning in that case.

### 3. Run the scene

Enter Play mode. The demo does not connect to any device on its own; use the buttons described below to start the monitor, enumerate devices, and observe events.

## Using the demo UI

| Control | Function |
|---------|----------|
| **Start** | Calls `wclSerialMonitor.Start` and begins receiving hot-plug events |
| **Stop** | Calls `wclSerialMonitor.Stop` and releases the platform notification handler |
| **Enum serial** | Clears the table, switches it to the 3-column serial layout, and calls `EnumSerialDevices` |
| **Enum USB** | Clears the table, switches it to the 7-column USB layout, and calls `EnumUsbDevices` |
| **Disable** | Calls `DisableUsbDevice` for the currently selected USB row |
| **Enable** | Calls `EnableUsbDevice` for the currently selected USB row |
| **Clear** | Empties the log window |
| **Devices table** | Displays either serial devices (`Device name`, `Friendly name`, `IsModem`) or USB devices (`Instance`, `Friendly name`, `VID`, `PID`, `Class`, `Manufacturer`, `Enabled`), depending on the last enumeration command |
| **Log window** | Receives messages from all monitor events and from every user action |

Selecting a row in the devices table marks it as the current target for the **Enable** and **Disable** buttons. Only USB rows carry a meaningful instance path, so those two buttons produce an informational message when a serial row is selected or when the table is currently showing serial devices.

---

## Behavioural notes

- **Start is required for hot-plug events.** `EnumSerialDevices` and `EnumUsbDevices` work at any time and return a snapshot of currently attached devices. The `OnSerialDeviceAdded`, `OnSerialDeviceRemoved`, `OnUsbDeviceAdded`, and `OnUsbDeviceRemoved` events fire only after `Start` has been called.
- **Events are delivered on the calling thread.** In this demo the monitor is started from the Unity main thread, so all handlers can safely update the UI without additional marshalling.
- **Enumeration replaces the table contents.** Each call to **Enum serial** or **Enum USB** clears the devices table and rebuilds it in the column layout appropriate for that mode. The header bar is shown or hidden accordingly.
- **USB enable and disable require elevation.** `EnableUsbDevice` and `DisableUsbDevice` change the driver state of the target device and require administrator privileges on Windows. Enumeration itself does not.
- **Device instance paths are the USB identifier.** The Enable and Disable buttons read the first column of the selected USB row and pass it to the framework unchanged.

---

## Platform notes

### Windows

- Serial enumeration returns short names (`COM1`, `COM4`, and so on).
- USB enumeration and `EnableUsbDevice` / `DisableUsbDevice` are fully supported.
- USB enable and disable require the application to run elevated.

### macOS

- Serial enumeration returns full device node paths, for example `/dev/cu.usbserial-1420` and `/dev/tty.*`.
- All serial events (`OnStarted`, `OnStopped`, `OnSerialDeviceAdded`, `OnSerialDeviceRemoved`) work identically to Windows.
- USB enumeration and USB enable/disable are Windows-specific and return an error code on macOS. The demo remains functional; the USB path simply yields no devices.

See the **Cross-platform notes: macOS** section on the official example page for a concise summary of these differences.

## Project structure

```
Assets/
├── Prefabs/
│   ├── SerialMonitorSerialRow.prefab    # Generated by the scene builder
│   ├── SerialMonitorUsbRow.prefab       # Generated by the scene builder
│   └── SerialMonitorLogRow.prefab       # Generated by the scene builder
├── Scripts/
│   ├── SerialMonitorSceneBuilder.cs     # Editor: Tools → Serial Monitor → Build Scene
│   └── SerialMonitorDemo.cs             # Runtime: all demo logic
└── Scenes/
    └── <your scene>                     # Saved by the scene builder
```

`SerialMonitorSceneBuilder.cs` is wrapped in `#if UNITY_EDITOR` and has no runtime footprint. `SerialMonitorDemo.cs` is a plain `MonoBehaviour` that uses only the public Serial Framework API.

The three row prefabs share a common `TableRowUI` component, which is responsible for populating cells and highlighting the selected row. This component is part of the demo and is reusable in applications that need tabular output for device lists or log entries.
