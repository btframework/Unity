# Serial OPP Client — Unity Demo

A Unity example demonstrating how to send files over a serial port using the OBEX **Object Push Profile (OPP)**, implemented with the **[Serial Framework](https://www.btframework.com/serialframework.htm)** (`wclSerialClient`, `wclSerialMonitor`, `wclObexOppClient`).

The OBEX protocol and the Object Push profile are described on the vendor's reference page:
**https://www.btframework.com/obex.htm**

---

## Overview

The example bridges an OBEX OPP client session onto a serial transport. It opens a serial port, establishes an OBEX session over it, then pushes a file from disk to the remote peer while displaying progress in the UI. All data written by the OBEX client is forwarded to the serial port, and all data received from the serial port is forwarded back into the OBEX client.

The user interface is generated programmatically by an editor script. There are no hand-authored scenes or prefabs to maintain, which keeps the example aligned with the framework API.

---

## Features demonstrated

| Area | API used |
|------|----------|
| Port enumeration | `wclSerialMonitor.EnumSerialDevices` |
| Hot-plug notifications | `wclSerialMonitor.OnSerialDeviceAdded`, `OnSerialDeviceRemoved` |
| Serial connection | `wclSerialClient.Connect`, `Disconnect`, `OnConnect`, `OnDisconnect` |
| Serial data pump | `wclSerialClient.OnData`, `wclSerialClient.Write`, `wclObexOppClient.ProcessData` |
| Port configuration | `wclSerialClient.GetConfig`, `SetConfig` (baud rate is forced to 115200, 8 data bits, on connect) |
| OBEX session | `wclObexOppClient.Connect`, `Disconnect` |
| OBEX file push | `wclObexOppClient.Put`, `OnProgress`, `OnPutComplete`, `OnWrite` |

## Getting started

### 1. Install the Serial Framework

Ensure that the Serial Framework assemblies (`wclCommon`, `wclCommunication`, `wclSerialFramework`, and their dependencies) are present in the Unity project and are referenced by the assembly that contains `SerialOppClientDemo.cs`.

### 2. Build the demo scene

The UI is generated by an editor script. From the Unity menu, select:

> **Tools → Serial OPP Client → Build Scene**

This operation performs the following:

- Creates the `SerialOppClientUI` canvas with the full control layout
- Creates the `SerialOppClientDemo` GameObject and wires every UI element to its corresponding field
- Creates the `SerialOppClientLogRow` prefab under `Assets/Prefabs`
- Saves the active scene so it is included in a build

After running the builder, save the scene manually (`Ctrl+S` / `Cmd+S`) if Unity does not save it automatically. The editor logs a warning in that case.

### 3. Run the scene

Enter Play mode. The demo starts monitoring serial devices on startup and fills the port dropdown with the currently attached devices.

## Using the demo UI

| Control | Function |
|---------|----------|
| **Select COM Port** | Dropdown listing the device names returned by `EnumSerialDevices` |
| **Refresh** | Re-enumerates serial devices and rebuilds the dropdown |
| **Connect / Disconnect** | Opens or closes the underlying `wclSerialClient` connection |
| **OBEX connect / OBEX disconnect** | Opens or closes the OBEX session with the target peer (`wclObexOppClient.Connect` / `Disconnect`) |
| **File path** | Path of the file to push |
| **Select file** | Opens a file picker (editor) or resolves to a default path (build) |
| **Send file** | Calls `wclObexOppClient.Put` with the selected file |
| **Progress bar** | Reflects `OnProgress` (bytes sent vs. total) |
| **Clear** | Empties the log window |
| **Log window** | Receives messages from the serial monitor, serial client, OBEX client, and user actions |

The order of operations is significant:

1. Select a port and click **Connect**. The demo waits for `OnConnect`, then queries the port configuration and forces 115200 baud, 8 data bits.
2. Click **OBEX connect** to open the OBEX session on top of the established serial connection.
3. Pick a file and click **Send file** to push it. The progress bar and log report the transfer.
4. Click **OBEX disconnect** and then **Disconnect** to tear down in reverse order.

## Behavioural notes

- **The OBEX client writes through the serial client.** `wclObexOppClient` does not talk to the OS directly. Its `OnWrite` event asks the application for a transport, and the demo implements that transport as `_client.Write(data, out written)`. Data coming the other way is delivered to `wclObexOppClient.ProcessData`.
- **Startup configuration is applied in `OnConnect`.** Once the serial connection is established, the demo calls `GetConfig`, sets `BaudRate = 115200` and `ByteSize = 8`, and pushes the result back with `SetConfig`. This assumes the peer uses the same settings; a different baud rate can be adopted by editing `ClientConnect`.
- **The port list refreshes on startup and on demand.** `wclSerialMonitor.Start` is called during `Start`, and the port list is refreshed both at startup and when the user clicks **Refresh**. Devices that appear or disappear after startup are also reported to the log through `OnSerialDeviceAdded` / `OnSerialDeviceRemoved`.
- **The file stream is owned by the OBEX client during the transfer.** `Put` is called with a `FileStream`; on success the stream is released in `OnPutComplete`, and on failure the demo releases it immediately after `Put` returns an error. This mirrors the lifetime contract on the reference page.
- **The peer must speak OBEX OPP over serial.** A raw serial echo or a terminal will not complete a session. The example is intended for use with a device or service that expects the OPP framing.

## Platform notes

### Windows

- Serial device names are short (`COM1`, `COM4`, and so on).
- Any message-processing method is acceptable when calling `Connect`.

### macOS

- Serial device names are full node paths, for example `/dev/cu.usbserial-1420`.
- When calling `Connect`, use `wclMessageProcessingMethod.mpAsync` so events are delivered on a worker thread. The demo uses the default overload; adjust `OnConnectClicked` accordingly if your deployment targets macOS.
- The serial transport, the OBEX client, and the OPP framing behave identically to Windows once the session is established.

See the **Cross-platform notes: macOS** section on the Serial Client reference page (**https://www.btframework.com/serialclient.htm**) for the exact `Connect` pattern.

## Project structure

```
Assets/
├── Prefabs/
│   └── SerialOppClientLogRow.prefab       # Generated by the scene builder
├── Scripts/
│   ├── SerialOppClientSceneBuilder.cs     # Editor: Tools → Serial OPP Client → Build Scene
│   └── SerialOppClientDemo.cs             # Runtime: all demo logic
└── Scenes/
    └── <your scene>                       # Saved by the scene builder
```

`SerialOppClientSceneBuilder.cs` is wrapped in `#if UNITY_EDITOR` and has no runtime footprint. `SerialOppClientDemo.cs` is a plain `MonoBehaviour` that uses only the public Serial Framework API.

The log row uses the shared `TableRowUI` component, which is also used by the Serial Client and Serial Monitor examples.
