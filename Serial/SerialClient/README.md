# Serial Client — Unity Demo

A Unity example demonstrating the use of the **[Serial Framework](https://www.btframework.com/serialframework.htm)** (`wclSerialClient` class) for serial port communication: opening a port, configuring it, exchanging data, and handling modem events.

This demo is a Unity port of the reference **Serial Client** sample documented at:
**https://www.btframework.com/serialclient.htm**

---

## Overview

The example implements a complete, event-driven serial communication workflow on Windows and macOS:

- Enumerating available COM ports and serial device nodes
- Opening a connection and handling asynchronous connect results
- Reading and writing the full port configuration (`wclSerialConfig`)
- Adjusting timeouts and buffer sizes
- Driving serial control lines (DTR, RTS, BREAK, XON, XOFF)
- Purging transmit and receive buffers
- Sending and receiving data, with an ASCII + line-feed convenience mode
- Logging line-status events, communication errors, and modem status in real time

The user interface is generated programmatically by an editor script. There are no hand-authored scenes or prefabs to maintain, which keeps the example aligned with the framework API.

---

## Features demonstrated

| Area | `wclSerialClient` API used |
|------|----------------------------|
| Port enumeration | `wclSerialMonitor.EnumSerialDevices` |
| Connect / disconnect | `Connect`, `Disconnect`, `OnConnect`, `OnDisconnect` |
| Configuration | `GetConfig`, `SetConfig`, `wclSerialConfig` (baud rate, byte size, parity, stop bits, flow control, XON/XOFF limits, special characters) |
| Timeouts | `GetTimeouts`, `SetTimeouts`, `wclSerialTimeouts`, `WriteTimeout` |
| Buffers | `GetReadBufferSize`, `SetReadBufferSize`, `GetWriteBufferSize`, `SetWriteBufferSize`, `FlushBuffers` |
| Control lines | `EscapeCommFunction`, `SetCommBreak`, `ClearCommBreak` |
| Buffer control | `PurgeComm` (`purgeRxAbort`, `purgeRxClear`, `purgeTxAbort`, `purgeTxClear`), `TransmitCommChar` |
| Data exchange | `Write`, `OnData` |
| Line and modem events | `OnEvents` (`wclSerialEvent`), `OnError` (`wclSerialError` + `wclSerialCommunicationState`), `OnReadError`, `GetModemStatus` |

## Getting started

### 1. Install the Serial Framework

Ensure that the Serial Framework assemblies (`wclCommon`, `wclSerialFramework`, and their dependencies) are present in the Unity project and are referenced by the assembly that contains `SerialClientDemo.cs`.

### 2. Build the demo scene

The UI is generated by an editor script. From the Unity menu, select:

> **Tools → Serial Client → Build Scene**

This operation performs the following:

- Creates the `SerialClientUI` canvas with the full control layout
- Creates the `SerialClientDemo` GameObject and wires every UI element to its corresponding field
- Creates the `SerialClientEventRow` prefab under `Assets/Prefabs`
- Saves the active scene so it is included in a build

After running the builder, save the scene manually (`Ctrl+S` / `Cmd+S`) if Unity does not save it automatically. The editor logs a warning in that case.

### 3. Run the scene

Enter Play mode, click **Enum**, select a port from the dropdown, and click **Connect**. The event log at the bottom of the window reports every operation.

## Using the demo UI

| Control | Function |
|---------|----------|
| **Enum** | Refreshes the list of available serial devices via `wclSerialMonitor` |
| **Ports dropdown** | The device name passed to `Connect` (e.g. `COM4` or `/dev/cu.usbserial-1420`) |
| **Connect / Disconnect** | Opens or closes the port |
| **Write timeout / Set write timeout** | Configures `wclSerialClient.WriteTimeout` |
| **Get / Set config** | Reads or applies a full `wclSerialConfig` (baud rate, parity, byte size, stop bits, flow control, XON/XOFF, special characters, DTR/RTS behaviour) |
| **Get / Set buffers** | Reads or writes the driver's RX/TX buffer sizes |
| **Get / Set timeouts** | Reads or writes `wclSerialTimeouts` (read interval, multipliers, constants) |
| **Set / Clear comm BREAK** | `SetCommBreak` / `ClearCommBreak` |
| **Function → Exec func** | `EscapeCommFunction` with one of the standard escape codes (set/clear DTR, RTS, BREAK, XON, XOFF) |
| **Purge** | `PurgeComm` with the selected RX/TX abort or clear flags |
| **Char code → Transmit** | `TransmitCommChar` — sends a single out-of-band byte |
| **Flush buffers** | `FlushBuffers` |
| **Send / Line feed / Clear** | Sends ASCII text (optionally appending CR, LF, or CR+LF) via `Write`; **Clear** empties the event log |
| **Event log** | Live stream of `OnConnect`, `OnData`, `OnDisconnect`, `OnError`, `OnReadError`, and `OnEvents` output, plus modem status from `GetModemStatus` |

After a successful connect, the demo automatically calls `GetConfig`, `GetTimeouts`, and `GetReadBufferSize` / `GetWriteBufferSize` so the UI reflects the current state of the port.

## Behavioural notes

- **`Connect()` is asynchronous.** The call returns immediately; the actual result — port opened, or an error code — is delivered in the `OnConnect` event's `Error` parameter. The demo follows this pattern and refreshes the configuration from within `ClientConnect`.
- **No synchronous `Read` is available.** Data is delivered exclusively through the `OnData` event. The framework does not frame the incoming bytes; protocol-level framing (delimiters, length prefixes) must be implemented by the application.
- **The demo sends ASCII text.** Payloads are encoded with `Encoding.ASCII`. Binary protocols should pass raw `byte[]` arrays to `Write`.
- **Errors and states are flag sets.** `OnError` and `OnEvents` deliver combined `wclSerialError`, `wclSerialCommunicationState`, and `wclSerialEvent` flags. The demo decodes each flag into a readable line in the log.

## Platform notes

### Windows

- Device names are short (`COM1`, `COM4`, and so on).
- Any message-processing method is acceptable when calling `Connect`.

### macOS

- Device names are full node paths, for example `/dev/cu.usbserial-1420`.
- When calling `Connect`, use `wclMessageProcessingMethod.mpAsync` so events are delivered on a worker thread.
- The remainder of the API — configuration, timeouts, buffers, events, `Write`, `PurgeComm`, `EscapeCommFunction` — behaves identically to Windows.

See the **Cross-platform notes: macOS** section on the official example page for the exact `Connect` pattern.

## Project structure

```
Assets/
├── Prefabs/
│   └── SerialClientEventRow.prefab      # Generated by the scene builder
├── Scripts/
│   ├── SerialClientSceneBuilder.cs      # Editor: Tools → Serial Client → Build Scene
│   └── SerialClientDemo.cs              # Runtime: all demo logic
└── Scenes/
    └── <your scene>                     # Saved by the scene builder
```

`SerialClientSceneBuilder.cs` is wrapped in `#if UNITY_EDITOR` and has no runtime footprint. `SerialClientDemo.cs` is a plain `MonoBehaviour` that uses only the public Serial Framework API.
