# Serial OPP Server — Unity Demo

A Unity example demonstrating how to receive files over a serial port using the OBEX **Object Push Profile (OPP)** as a server, implemented with the **[Serial Framework](https://www.btframework.com/serialframework.htm)** (`wclSerialClient`, `wclSerialMonitor`, `wclObexOppServer`).

The OBEX protocol and the Object Push profile are described on the vendor's reference page:
**https://www.btframework.com/obex.htm**

---

## Overview

The example bridges an OBEX OPP server session onto a serial transport. It opens a serial port, forwards all received serial bytes into a `wclObexOppServer` instance, and lets the server negotiate incoming OBEX connections and file transfers. Any data the server needs to send back is written out through the same serial port. Incoming file transfers are reported in the log, and their progress is reflected in the UI.

The user interface is generated programmatically by an editor script. There are no hand-authored scenes or prefabs to maintain, which keeps the example aligned with the framework API.

---

## Features demonstrated

| Area | API used |
|------|----------|
| Port enumeration | `wclSerialMonitor.EnumSerialDevices` |
| Hot-plug notifications | `wclSerialMonitor.OnSerialDeviceAdded`, `OnSerialDeviceRemoved` |
| Serial connection | `wclSerialClient.Connect`, `Disconnect`, `OnConnect`, `OnDisconnect` |
| Serial data pump | `wclSerialClient.OnData`, `wclSerialClient.Write`, `wclObexOppServer.ProcessData` |
| Port configuration | `wclSerialClient.GetConfig`, `SetConfig` (baud rate is forced to 115200, 8 data bits, on connect) |
| OBEX server session | `wclObexOppServer.Accept`, `OnConnect`, `OnDisconnected` |
| OBEX file receipt | `OnPutBegin`, `OnPutProgress`, `OnPutCompleted`, `OnWrite` |

- **Unity** 2021.3 LTS or newer (TextMeshPro and the Editor API are used)
- **Serial Framework** installed and referenced by the project
  - Product page: https://www.btframework.com/serialframework.htm
  - Installation guide: https://www.btframework.com/howtoinstall.htm
- **Platforms:** Windows and macOS
- Both **Mono** and **IL2CPP** scripting backends are supported without additional configuration
- The remote peer must act as an OBEX OPP client and speak OPP over the same serial transport; a plain serial terminal will not initiate a session

## Getting started

### 1. Install the Serial Framework

Ensure that the Serial Framework assemblies (`wclCommon`, `wclCommunication`, `wclSerialFramework`, and their dependencies) are present in the Unity project and are referenced by the assembly that contains `SerialOppServerDemo.cs`.

### 2. Build the demo scene

The UI is generated by an editor script. From the Unity menu, select:

> **Tools → Serial OPP Server → Build Scene**

This operation performs the following:

- Creates the `SerialOppServerUI` canvas with the full control layout
- Creates the `SerialOppServerDemo` GameObject and wires every UI element to its corresponding field
- Creates the `SerialOppServerLogRow` prefab under `Assets/Prefabs`
- Saves the active scene so it is included in a build

After running the builder, save the scene manually (`Ctrl+S` / `Cmd+S`) if Unity does not save it automatically. The editor logs a warning in that case.

### 3. Run the scene

Enter Play mode. The demo starts monitoring serial devices on startup and fills the port dropdown with the currently attached devices.

## Using the demo UI

| Control | Function |
|---------|----------|
| **Select COM Port** | Dropdown listing the device names returned by `EnumSerialDevices` |
| **Refresh** | Re-enumerates serial devices and rebuilds the dropdown |
| **Connect / Disconnect** | Opens or closes the underlying `wclSerialClient` connection |
| **Progress bar** | Reflects `OnPutProgress` (bytes received vs. total) |
| **Clear** | Empties the log window |
| **Log window** | Receives messages from the serial monitor, serial client, OBEX server, and user actions |

The order of operations is significant:

1. Select a port and click **Connect**. The demo waits for `OnConnect`, then queries the port configuration and forces 115200 baud, 8 data bits.
2. The remote OPP client initiates the session. When its OBEX CONNECT arrives over the serial transport, `OnConnect` fires and the server responds via `Accept`.
3. When the client starts sending a file, `OnPutBegin` is called and the transfer begins. `OnPutProgress` updates the progress bar, and `OnPutCompleted` reports the final result.
4. Click **Disconnect** to close the serial port when the session is over.

## Behavioural notes

- **The OBEX server writes through the serial client.** `wclObexOppServer` does not talk to the OS directly. Its `OnWrite` event asks the application for a transport, and the demo implements that transport as `_client.Write(data, out written)`. Data coming the other way is delivered to `wclObexOppServer.ProcessData`.
- **Startup configuration is applied in `OnConnect`.** Once the serial connection is established, the demo calls `GetConfig`, sets `BaudRate = 115200` and `ByteSize = 8`, and pushes the result back with `SetConfig`. This assumes the peer uses the same settings; a different baud rate can be adopted by editing `ClientConnect`.
- **Connections and transfers are auto-accepted.** `OppServerConnect` calls `Accept` for every incoming OBEX CONNECT, and `OppServerPutBegin` returns `accept = true` for every incoming file. A production implementation would instead prompt the user or apply a policy based on the peer, name, and MIME type.
- **`OppServerPutCompleted` reports the outcome.** The handler receives the error code and the stream with the received object, and returns `accept = true` or `false` to confirm or reject the transfer. The demo currently accepts everything and logs the result.
- **The port list refreshes on startup and on demand.** `wclSerialMonitor.Start` is called during `Start`, and the port list is refreshed both at startup and when the user clicks **Refresh**. Devices that appear or disappear after startup are also reported to the log through `OnSerialDeviceAdded` / `OnSerialDeviceRemoved`.
- **The peer must speak OBEX OPP over serial.** A raw serial echo or a terminal will not initiate a session. The example is intended for use with a device or service that acts as an OPP client over the same serial transport.

## Platform notes

### Windows

- Serial device names are short (`COM1`, `COM4`, and so on).
- Any message-processing method is acceptable when calling `Connect`.

### macOS

- Serial device names are full node paths, for example `/dev/cu.usbserial-1420`.
- When calling `Connect`, use `wclMessageProcessingMethod.mpAsync` so events are delivered on a worker thread. The demo uses the default overload; adjust `OnConnectClicked` accordingly if your deployment targets macOS.
- The serial transport, the OBEX server, and the OPP framing behave identically to Windows once the session is established.

See the **Cross-platform notes: macOS** section on the Serial Client reference page (**https://www.btframework.com/serialclient.htm**) for the exact `Connect` pattern.

## Project structure

```
Assets/
├── Prefabs/
│   └── SerialOppServerLogRow.prefab       # Generated by the scene builder
├── Scripts/
│   ├── SerialOppServerSceneBuilder.cs     # Editor: Tools → Serial OPP Server → Build Scene
│   └── SerialOppServerDemo.cs             # Runtime: all demo logic
└── Scenes/
    └── <your scene>                       # Saved by the scene builder
```

`SerialOppServerSceneBuilder.cs` is wrapped in `#if UNITY_EDITOR` and has no runtime footprint. `SerialOppServerDemo.cs` is a plain `MonoBehaviour` that uses only the public Serial Framework API.

The log row uses the shared `TableRowUI` component, which is also used by the Serial Client, Serial Monitor, and Serial OPP Client examples.
